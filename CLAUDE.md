# IBM Z Datathon 2026 — Federated Learning prep

Goal: build a privacy-preserving federated learning demo (Flower + PyTorch, later Opacus DP and SecAgg+) for the "AI Secured: Innovation Without Exposure" track.

## Use the knowledge graph first
`graphify-out/` holds a knowledge graph of this folder. Before grepping or reading files, consult
`graphify-out/GRAPH_REPORT.md`, then use `graphify explain "<node>"` / `graphify path "A" "B"`.
After changing code run `graphify update .`; after changing docs/notes run `/graphify --update`.

## Layout
- `IBM HACKATHON LEARNING.txt` — learning progress summary (theory done; next is implementation).
- `step1_flower_fedavg.py` — Step 1: FedAvg, 3 non-IID simulated hospitals. Run with `.venv\Scripts\python.exe`.
- `artifacts/` — local copies of the three claude.ai artifacts (each `index.html`): Z Datathon Playbook, Corporate AI Circuit, Federated Learning Toolkit.
- `.venv/` — Python 3.14 venv (torch, flwr, ray, scikit-learn, pandas). Ignored by graphify via `.graphifyignore`.

## Teaching preference
Teach like a mentor: intuition -> simple example -> technical detail -> quiz -> implementation. Explain code in small pieces; don't dump big codebases. Don't re-teach completed theory (FedAvg, non-IID, FedProx, DP, SecAgg).
- `step2_heart_fedavg_fedprox.py` — Step 2: FedAvg vs FedProx on UCI Heart Disease with its 4 real hospitals. Sweep: `run_step2_sweep.sh` -> `results/step2_runs.jsonl`. Finding: FedProx ~ FedAvg; FedAvg ~ centralized.
- `data/heart_disease/` — NOT in git. Download the 4 files `processed.{cleveland,hungarian,switzerland,va}.data` from https://archive.ics.uci.edu/ml/machine-learning-databases/heart-disease/
- `step3_heart_dp.py` — Step 3: Step 2 + Opacus DP-SGD (Poisson sampling, clip, noise; per-hospital RDP epsilon over all rounds). Env: NOISE, CLIP, DELTA. `test_step3_dp.py` = unit checks (prox changes weights, epsilon monotone, accountant cross-check). Sweep: `run_step3_sweep.sh` -> `results/step3_runs.jsonl`. Finding: accuracy 0.767 (NOISE 0) -> 0.758-0.760 (NOISE 2), vs 0.778 at step 2; FedProx ~ FedAvg; max epsilon is large (12 at noise 2, 166 at noise 0.5) because hospitals are small, so the privacy cost shows up in epsilon, not accuracy.
- `step4_heart_secagg.py` — Step 4: Step 3 (imports its data/model/DP code unchanged) + Flower SecAgg+ via new-style `ServerApp` (`@app.main`, `LegacyContext`, `SecAggPlusWorkflow(num_shares=4, reconstruction_threshold=3, max_weight=300, clipping_range=8)`) and `secaggplus_mod` on the ClientApp. Env `SECAGG` (0/1, default 1) plus all step-3 env vars. `test_step4_secagg.py` = 4 checks (SECAGG=0 equals step 3; ON vs OFF within quantization error; max|w| < clipping range; FedProx mu reaches clients). Sweep: `run_step4_sweep.sh` -> `results/step4_runs.jsonl` (30 SecAgg runs + 6 SECAGG=0 timing runs). Finding: SecAgg ON gives the same mean accuracy as step 3 (5 seeds, 3 dp: e.g. 0.766 at noise 1, 0.758 at noise 2) and the same epsilon, because the server only sees the sum and quantization error is ~4e-6; cost is ~0.4-0.5 s/round more (2.0-2.6 vs 1.5-2.1 s).
- Step 4 limits (be honest in the demo): the simulation is ONE machine/process, so it demonstrates the protocol, not network security; the threat model is an honest-but-curious server (follows the protocol, tries to read updates); SecAgg hides single updates only inside the sum, so with 4 hospitals, 3 colluding with the server reveal the 4th's update. SecAgg does not replace DP: the released model still needs DP (step 3). Values beyond +-8 after scaling are silently clipped; the run asserts max|w| < 8.
- `dashboard/` — Step 5: live privacy dashboard (FastAPI + SSE + plain JS). Start: `.venv\Scripts\python.exe -m dashboard.server` then open http://127.0.0.1:8000 (env `HOST`, `PORT`; set `HOST=0.0.0.0` in Docker). `server.py` starts `step4_heart_secagg.py` as a subprocess (one run at a time, own process group, whole tree killed on stop/crash/shutdown) and tails its hook files. `sweeps.py` (+ `test_sweeps.py`) turns `results/step3_runs.jsonl`/`step4_runs.jsonl` into the privacy-vs-accuracy data. `static/` = UI, `replays/golden_run.jsonl` (+ folder `golden_run/`) = committed recorded run for the no-training fallback, `runs/` = every live run's files (gitignored). Plan: `.claude/plans/dashboard.md`. Tests: `test_dashboard.py` (a few minutes, runs real simulations) and `dashboard/test_sweeps.py`.
- Step 5 hooks in `step4_heart_secagg.py` (all unset = identical behaviour): `EVENTS_FILE` (server appends `baseline` and per-round `round` JSON lines), `INSPECT_DIR` + `INSPECT_ROUND` (default 1) (client mod `inspector_mod`, placed OUTSIDE `secaggplus_mod`, writes `stages_h<pid>.jsonl` (one file per hospital), and for hospital 0 `plain.npy`, `masked.npy`, `inspect.json`, `aggregate.npy`). The masked vector is the model's 273 parameters + 1 leading example-count slot (274 values, uint32 mod 2^32).
- Step 5 frontend (redesign): fonts IBM Plex Sans 400/600/700 + Mono 400 (latin, OFL) are vendored in `dashboard/static/vendor/fonts/` (from `@ibm/plex-sans@1.1.0`, `@ibm/plex-mono@2.5.0`; the full `@ibm/plex` package is too big for jsdelivr). Layout: sticky header with scrollspy nav, hero (headline + canvas cipher strip), then a two-column shell with a sticky run-console rail (>=1100 px; a full-width block at 768-1099; one column <640). Gold token = locked/protected, teal token = model.
- `step6_heart_deploy.py` — Step 6: step 4 as a Flower **deployment** (1 SuperLink + 4 SuperNodes, one per hospital, no Ray; Ray has no s390x wheels). Reuses step 3/4 code unchanged. Per-run parameters travel as Flower run_config (keys in `pyproject.toml`: rounds, noise, clip, delta, strategy, mu, seed, secagg, local-epochs, events-file, inspect-dir, inspect-round, debug-dir; floats need a decimal point) and `apply_run_config` copies them into the step-3/step-4 module globals on both sides. The ServerApp runs `s3.baselines()` BEFORE building the strategy (same torch RNG order as step 4) and ends with `RESULT {json}` plus a `done` event. `step3_heart_dp.py` got env `DATA_DIR` and `ALLOW_MISSING_DATA=1` (a SuperNode holds only its own file; the other DATA entries are None).
- Step 6 commands: native (no Docker) `.venv\Scripts\python.exe run_step6_local.py rounds=3 secagg=1 noise=1.0` (own temp work dir, own FLWR_HOME, per-hospital data folders, kills the whole process tree); Docker `docker compose -f deploy/docker-compose.yml up --build` then http://127.0.0.1:8000 (`DASHBOARD_PORT=8001` if the port is taken); tests `.venv\Scripts\python.exe test_step6_deploy.py` (about 15 min).
- Step 6 findings: deployment SECAGG=0 equals the step 4 simulation EXACTLY (acc, F1, per-hospital acc, epsilon, baselines: diff 0.0, FedAvg and FedProx, 3 rounds, seed 0); SecAgg ON within the quantization bound (3.75e-6 vs bound 6.64e-6 after 1 round), same epsilon. In Docker (amd64) each SuperNode sees only `/data/processed.<its hospital>.data`. Dashboard `MODE=deploy` runs `flwr run --stream` and stops with `flwr stop`; default `MODE=sim` is unchanged.
- Step 6 limits (be honest): the SuperLink container holds all four files, because the ServerApp computes the non-private baselines and the pooled test score (evaluation only); the shared `/runs` volume is the demo's inspector channel; gRPC is insecure (no TLS) and the dashboard has no login (published on loopback only). Flower 1.37 uses `$FLWR_HOME/config.toml` (`[superlink.<name>] address insecure`), not federations in pyproject; SuperLink Control/Runtime API is HTTP on `--port` (default 8000, which clashes with the dashboard: we use 9093).
- Step 6 s390x (QEMU rehearsal, 2026-10-10): `deploy/Dockerfile` builds for linux/s390x (174 min under QEMU, mostly compiling grpcio) and a 1-round SecAgg run completes on s390x (`uname -m` = s390x, big-endian `>u4` masked vector); a MIXED run (amd64 SuperLink + 3 SuperNodes, hungarian SuperNode s390x, `deploy/docker-compose.mixed.yml`) gives the same accuracy as all-s390x. Problems found and fixed: pip read timeout, missing libopenblas0, protobuf C extension segfault on s390x (pure-Python via a `.pth`), and a byte-order bug in `set_parameters` (arrays from a little-endian server rejected by a big-endian client; SecAgg+ hid it as a dropped hospital). Unresolved under QEMU: interpreter-exit segfault in processes that import protobuf. Not verified on real LinuxONE. Runbook: `deploy/LINUXONE.md`.
